# C0: the authorship loop — implementation and acceptance

Updated September 10, 2026. Status: implemented locally; the core reading → writing → Keep → return journey is now browser-verified. Final input-modality, live companion and human acceptance remain open. Confidence is high in the tested persistence/context contracts and observed local journey. This report records the first chapter of the approved authorship roadmap, not a replacement specification or a release claim.

## What this run builds

An ordinary Wiki sentence opens into one place to think. Bring one deliberately chosen owned Library highlight or exact article excerpt beyond its attached passages; inspect the surrounding words, place it, or undo the placement without undoing your writing. The existing companion receives the current sentence, server-resolved passages, your private writing, question, and named hypothetical. Writing or moving material does not launch a model call.

Write without naming anything first. Select a phrase and make it the title without removing it from the body. Close preserves authored work. The modest “Your work here” list uses your title or words; if the original claim disappears, it exposes the complete saved context for recovery. Earlier premises and proposals remain readable when a sentence changes, with an explicit action to continue against the current sentence.

Private work now has account-scoped server persistence, acknowledgment-based save status, device recovery, serialized saves, revision conflicts with both versions inspectable, and explicit Discard. Temporary drafts produce no Notebook embeddings or Wiki maintenance source events. Keep creates a real Notebook note or Question using ordinary destination policy, preserves both bound passages and structured origin links, and leaves the exploration intact. Each exploration keeps at most one copy in each destination; retries return that copy. Later private writing does not silently rewrite a kept copy.

Accepted Wiki wording still changes only through the existing guarded acceptance action. Specialized Wiki exclusions, ordinary Library exploration, and natural agent routing remain intact.

- `AuthoredWorkOrigin` replaces generated plaintext origin paragraphs with one shared dated return footer in Notebook and Questions. Source quotation presentation preserves the distinction between authored prose and source words.
- `sourceRoutes` now supplies one saved-source path resolver for quotation links and both destination footers, replacing the separate Question and footer validation. The Question footer names both saved sources; long source titles can wrap rather than forcing overflow.
- `authoredKeepEffects` replaces the inline fire-and-forget Keep callbacks in `server.js`. It writes to the existing embedding and source-event queues with stable target identities; no new queue, worker or collection was added. The shared embedding job builders replace inline Notebook/Question payload construction, and strict durable enqueue is opt-in for Keep.
- Keyboard preview entry now focuses Back only if the initiating result retained focus; Back restores that exact result, and closing cancels pending focus. The title action replaces its mouse-only selection handler with one pointer handler for mouse, touch and stylus. The dossier case cover replaces viewport-based heading/action rules with a container query at 620px, preventing long action buttons from squeezing the introduction beside the agent rail. No parallel control path or dependency was added.
- The final input pass gives the quiet margin mark a 44 × 44px hit area and the kept-copy links and Discard control a minimum 44px height. Source and kept-copy links share the existing actions rule; the redundant source-link class and selector were removed. No component or dependency was added.
- Input-method confirmation and cancellation now stay with the input method: three guards in the existing Rename, chooser and pocket handlers prevent Enter from prematurely saving a title and Escape from dismissing the working surface during composition. They recognize both `isComposing` and the 229 composition key signal. No new state, helper, component or dependency was introduced. A bounded binding audit found no unused top-level bindings in the five authored-pocket components checked; no speculative deletion was made.
- A stale Discard now exposes the server's newer version through the existing conflict mechanism without advancing deletion authority. Discard stays unavailable until the person chooses a version, and choosing does not itself delete anything. `AuthoredConflict` replaces the inline conflict UI in `AuthoredWriting.jsx` and is reused by removed-sentence recovery. That recovery offers the saved version without offering a fresh save against a missing sentence. Resolving clears the stale operation error. No new file, persistence system, endpoint or dependency was added.
- Save, Keep and Discard now use one `conflictFrom` check instead of separate revision-response checks. A stale fresh Keep exposes both versions without replacing private words or creating a copy. Fresh Keep buttons wait for a choice; existing interrupted Keeps still resume their immutable reservation. Choosing a version is separate from explicitly keeping it. This reuses the conflict UI, adds no file or dependency, and preserves the existing retry mutation identity.
- The device recovery cache now stores only unsaved draft/revision data, exact pending save requests and Keep retry identities. It no longer serializes full server records, conflict snapshots or transient operation state. Acknowledgement removes the recovery entry; opening a page also removes its obsolete clean cache. Legacy dirty caches remain readable and server-known Keep reservations still come from load. Invalid non-object cache data falls back to the server copy. This replaces whole-record serialization in the existing hook; no new file, dependency or schema was added.
- Reopening an acknowledged pocket no longer creates a redundant save. Draft extraction omits null optional fields, matching server normalization; the reader's restored empty comparison therefore does not count as an edit. Clearing a real comparison, premise or selected source still sends a replacement draft and removes that field. This is one filter-condition change, with no new comparison helper, dependency or persistence path.
- Regression and local-fixture files are verification support. No package dependency was added. Local dependency symlinks and database/log output are excluded from product changes.
- The browser pass removed Library's redundant default-scope URL rewrite, which discarded exact-passage fragments, and 66 lines of duplicate citation positioning that overlapped the agent rail. Marginalia now depends on the reader's available width. Existing Question mobile rules were moved after their desktop definitions so the evidence column stacks below the writing. Search shows “Looking…” throughout its debounce and clears stale results immediately. Keep receipts preserve title punctuation; Retry uses the existing accessible control styling.

## Current Keep completion contract

A reserved Keep finishes only after its normal background work has durable queue records. The copy can exist while that finishing step is interrupted; the response then explicitly acknowledges the reservation and the UI offers **Finish keeping note/question**.
